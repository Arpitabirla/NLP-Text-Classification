Introduction & Objectives

1.1   What is Natural Language Processing?

Natural Language Processing (NLP) is a branch of Artificial Intelligence (AI) that focuses on the interaction between computers and human (natural) language. It enables machines to read, understand, interpret, and generate text in a meaningful and contextually accurate way. NLP sits at the intersection of computer science, linguistics, and statistics.

The core challenge in NLP is that human language is inherently ambiguous, context-dependent, and ever-evolving. Words carry different meanings depending on context, grammar, and intent. NLP techniques provide a structured pipeline to convert raw unstructured text into machine-readable numerical representations suitable for downstream tasks such as classification, translation, sentiment analysis, and question answering.

Chapter 2 — Tokenization NLP Mini Project Report
Chapter 2
Tokenization
Definition

Tokenization is the process of splitting a string of text into a list of tokens (words, sentences, or subwords). It is the first and most fundamental step in any NLP pipeline.

2.1   Word Tokenization

Word tokenization splits a text into individual words and punctuation marks. NLTK's word_tokenize() function uses the Penn Treebank tokenizer, which handles contractions (e.g., "don't" → ["do", "n't"]), punctuation, and abbreviations intelligently.

Python Code
from nltk.tokenize import word_tokenize
tokens = word_tokenize("The running dogs are happily playing.")
# Output: ['The', 'running', 'dogs', 'are', 'happily', 'playing', '.']

2.2   Sentence Tokenization

Sentence tokenization (or sentence boundary detection) splits a paragraph into individual sentences using NLTK's sent_tokenize(), which uses a Punkt model trained on unsupervised data. It correctly handles abbreviations and special cases.

Terminal Output — Sentence Tokenization (3 sentences)

2.3   Stopword Removal

After tokenization, stopwords — extremely common words such as "the", "is", "and", "a" — are removed. These words carry little semantic information and can degrade model performance if included in feature vectors. NLTK provides a list of 179 English stopwords via nltk.corpus.stopwords.

Chapter 3 — Stemming NLP Mini Project Report
Chapter 3
Stemming
Definition

Stemming is the process of reducing a word to its root or base form by removing suffixes and prefixes using heuristic rules. The resulting stem may not be a valid dictionary word.

Stemming is widely used in Information Retrieval systems (search engines) where speed is more important than linguistic precision. The goal is to ensure that words like "run", "running", "runs", and "runner" all map to the same stem — "run".

3.1   Porter Stemmer

The Porter Stemming Algorithm, proposed by Martin Porter in 1980, is one of the most well-known stemming algorithms. It applies a sequence of five steps, each stripping a set of suffixes from the word using a measure of the stem's remaining length. While fast and simple, it can produce non-word stems (e.g., "beautiful" → "beauti").

Python Code — Porter Stemmer
from nltk.stem import PorterStemmer
stemmer = PorterStemmer()
print(stemmer.stem("running")) # → run
print(stemmer.stem("beautiful")) # → beauti
print(stemmer.stem("processing")) # → process

3.2   Snowball Stemmer

The Snowball Stemmer (also called the English Stemmer) is an improved version of the Porter Stemmer. It is part of the Snowball programming framework for designing stemming algorithms. Snowball is slightly more aggressive and supports multiple languages including English, French, German, Spanish, and more.

Python Code — Snowball Stemmer
from nltk.stem import SnowballStemmer
stemmer = SnowballStemmer("english")
print(stemmer.stem("generate")) # → generat
print(stemmer.stem("languages")) # → languag

  • Porter and Snowball produce identical results for most common words.

  • Both stemmers may produce non-dictionary words (e.g., "beauti", "artifici").
  • Stemming is faster than lemmatization but less accurate linguistically.

Chapter 4 — Lemmatization NLP Mini Project Report
Chapter 4
Lemmatization
Definition

Lemmatization is the process of reducing a word to its base or dictionary form (called the lemma), using vocabulary and morphological analysis. Unlike stemming, lemmatization always returns a valid dictionary word.

4.1   WordNet Lemmatizer

NLTK provides the WordNetLemmatizer, which uses the WordNet lexical database — a large English lexical resource containing over 155,000 words organized into synonym sets. Lemmatization is POS-tag aware, meaning that the same word can produce different lemmas depending on whether it is used as a verb, noun, or adjective.

For example, "better" as an adjective lemmatizes to "good", while as a verb it lemmatizes to "better". Without POS tags, the lemmatizer defaults to treating words as nouns, which reduces accuracy significantly.

Python Code — POS-Aware Lemmatization
from nltk.stem import WordNetLemmatizer
from nltk import pos_tag
lemmatizer = WordNetLemmatizer()

# Without POS tag (defaults to NOUN):
lemmatizer.lemmatize("running") # → running (WRONG!)

# With POS tag (verb context):
lemmatizer.lemmatize("running", "v") # → run (CORRECT!)
lemmatizer.lemmatize("dogs", "n") # → dog
lemmatizer.lemmatize("better", "a") # → good

Stemming vs Lemmatization — When to Use Which?
  • Use Stemming when speed is critical (search engines, real-time systems) and linguistic accuracy is secondary.
  • Use Lemmatization when accuracy is important (QA systems, chatbots, sentiment analysis, machine translation).
  • Lemmatization always produces valid dictionary words; stemming may not.
  • Lemmatization is computationally slower but semantically superior.

Chapter 5
Bag of Words (BOW)
Definition

The Bag of Words (BOW) model represents a text document as an unordered collection (multiset) of its words, disregarding grammar and word order but keeping multiplicity (frequency count).

5.1   Manual Implementation from Scratch

In our implementation, we first built a global vocabulary from all documents, assigning each unique word a unique integer index. Then for each document, we created a vector of size equal to the vocabulary, filling it with word counts. This clearly demonstrates the internal mechanics of the BOW model.

Algorithm — BOW from Scratch
Step 1: Build vocabulary V = {all unique words across all docs}
Step 2: For each document d:
vector[i] = count of V[i] in document d
Step 3: Return Document-Term Matrix (DTM) of shape (n_docs × |V|)

Limitations of Bag of Words
  • Order-insensitive: "I love NLP" and "NLP love I" produce the same BOW vector.
  • High dimensionality: The vocabulary can be very large for large corpora.
  • No semantic understanding: Synonyms like "happy" and "joyful" are treated as different words.
  • Bias towards common words: Words like "the", "is" dominate if stopwords are not removed.

Chapter 6 — TF-IDF NLP Mini Project Report
Chapter 6
TF-IDF (Term Frequency – Inverse Document Frequency)
Definition

TF-IDF is a numerical statistic used to reflect how important a word is to a document within a corpus. It penalizes words that appear frequently across all documents and rewards words that are important to a specific document.

6.1   Mathematical Formulation

The TF-IDF score of a term t in document d is the product of two quantities: Term Frequency (TF) and Inverse Document Frequency (IDF).

Mathematical Formulas
TF(t, d) = count(t in d) / total_words_in_d

IDF(t) = log( N / (1 + df(t)) ) + 1
where N = total number of documents
df = number of documents containing term t
+1 = smoothing to avoid log(0)

TF-IDF(t, d) = TF(t, d) × IDF(t)

A high TF-IDF score means the word appears frequently in the document (high TF) but rarely across other documents (high IDF) — making it a distinctive and important term. Common words like "the" have a very low IDF because they appear in almost every document.

Text Classification

Text classification is the task of assigning predefined categories to text documents. In this project, we demonstrate sentiment classification — determining whether a movie review is positive or negative — using the feature representations developed in previous chapters.

7.1   Dataset: NLTK Movie Reviews

We use the NLTK Movie Reviews corpus, a benchmark dataset for sentiment analysis. The corpus was originally collected by Bo Pang and Lillian Lee and consists of 2,000 movie reviews from the IMDB website, split evenly between 1,000 positive and 1,000 negative reviews.

7.2   Classification Models

We trained three classification pipelines on this dataset, each combining a different feature extraction method with a machine learning algorithm:

Pipeline 1: BOW + Multinomial Naive Bayes

CountVectorizer (max_features=5000, unigrams+bigrams) is used to extract BOW features, which are then passed to a MultinomialNB classifier (alpha=0.1). Naive Bayes is a probabilistic classifier based on Bayes' Theorem with the "naive" assumption of feature independence.

Pipeline 2: TF-IDF + Logistic Regression

TfidfVectorizer (max_features=5000, sublinear_tf=True, unigrams+bigrams) provides TF-IDF features. Logistic Regression is a linear classifier that models the probability of the positive class using the sigmoid function, optimized via L-BFGS.

Pipeline 3: TF-IDF + Linear SVM

TfidfVectorizer with LinearSVC (C=1.0) — a Support Vector Machine with a linear kernel. SVMs are particularly effective for high-dimensional sparse text features, finding the maximum-margin hyperplane separating the two classes.

Python Code — sklearn Pipeline
from sklearn.pipeline import Pipeline
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression

pipeline = Pipeline([
("tfidf", TfidfVectorizer(max_features=5000, sublinear_tf=True)),
("clf", LogisticRegression(max_iter=1000, C=1.0)),
])
pipeline.fit(X_train, y_train)
accuracy = pipeline.score(X_test, y_test)

Chapter 9 — Conclusion & Future Scope NLP Mini Project Report
Chapter 9
Conclusion & Future Scope

9.1   Conclusion

This mini project successfully demonstrates the implementation and practical application of fundamental Natural Language Processing techniques. Starting from raw, unstructured text, we built a complete NLP pipeline that transforms it into machine-readable numerical representations suitable for machine learning tasks.

Through hands-on implementation and real terminal output verification, the following key insights were established:

Key Findings
  • Tokenization is the essential first step — NLTK's word_tokenize intelligently handles contractions, abbreviations, and punctuation better than simple splitting on whitespace.
  • Stopword removal reduced our token count by ~34.5%, significantly reducing computational overhead without losing semantic content.
  • Stemming (Porter and Snowball) is fast but produces non-dictionary words like "beauti", "artifici", and "happili". Snowball is marginally more aggressive than Porter.
  • Lemmatization always produces valid dictionary words and is semantically superior, but requires POS-tagging for best results. Without POS context, accuracy degrades significantly.
  • Bag of Words provides a simple yet effective baseline. However, it treats all words equally regardless of their document-level importance.
  • TF-IDF overcomes BOW's main weakness by down-weighting common words. It correctly identified "artificial + intelligence", "machine + learning", and "natural + language" as the most important terms for their respective documents.
  • Text Classification results show that TF-IDF features consistently outperform raw BOW features across all classifiers. Linear SVM achieved the highest accuracy of ~87.75% on the Movie Reviews dataset.

The project also produced an interactive web dashboard that allows users to enter any text and visualize the complete NLP pipeline — from tokenization to TF-IDF scoring — in real time, making it an effective educational tool.

9.2   Limitations

The current implementation has several limitations: BOW and TF-IDF both ignore word order and context (e.g., "not good" and "good" would be treated similarly). Stemming produces linguistically incorrect stems. The classifier is trained only on movie reviews and may not generalize well to other domains.
